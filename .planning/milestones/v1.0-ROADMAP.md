# v1.0 Roadmap Archive — Procurement Intelligence Platform

**Milestone:** v1.0
**Completed:** 2026-02-24
**Archived:** 2026-02-25

## Overview

Five phases built the platform in strict dependency order: infrastructure and schema first, then the scraper pipeline that populates data, then the search layer that queries it, then the web application that delivers it to the BD team, and finally scheduling and hardening that automate and protect it. Each phase delivered a coherent, independently verifiable capability. The BD team started using the platform daily once Phase 4 shipped.

## Key Accomplishments

1. **AI-powered scraper pipeline** covering 63 Canadian procurement portals with Browser Use + instructor extraction, CanadaBuys CSV ingestion, and per-portal error isolation
2. **Hybrid search engine** combining full-text keyword search, pgvector semantic search, and Reciprocal Rank Fusion ranking with 6 filter dimensions
3. **Next.js dashboard** with Auth.js authentication, URL-encoded search state, listing detail slide-out, "New" badges, and scraper health monitoring
4. **Production-ready infrastructure** on AWS EC2 (ca-central-1) with Docker Compose, PostgreSQL + pgvector, Nginx TLS, and Terraform provisioning
5. **Automated nightly operations** with cron scheduling, flock overlap protection, retention cleanup, and Docker image pruning

## Phases

### Phase 1: Infrastructure (1 plan, complete 2026-02-24)
**Goal**: The EC2 instance is live, all services run in Docker Compose, PostgreSQL has the complete schema with all indexes and constraints, and TLS is terminated — ready to receive data.
**Requirements**: INFR-01, INFR-02, INFR-03, INFR-04
**Success Criteria**:
  1. `docker compose up` on EC2 starts all services without errors
  2. PostgreSQL schema contains all tables with HNSW index, tsvector GIN index, TIMESTAMPTZ columns, and composite unique constraint
  3. Terraform apply provisions EC2 in ca-central-1 with no drift
  4. HTTPS resolves at procurement.eliastools.com with valid TLS certificate
**Plans**:
- 1-01: Full infrastructure — Docker Compose scaffold, PostgreSQL schema + portal seed, Terraform AWS provisioning, EC2 deployment with TLS

### Phase 2: Scraper Pipeline (4 plans, complete 2026-02-24)
**Goal**: The scraper runs manually against all 63 portals, populates listings into PostgreSQL with valid structured fields and embeddings, and logs per-portal audit data — ready to be queried.
**Requirements**: SCRP-01, SCRP-02, SCRP-03, SCRP-04, SCRP-05, SCRP-06
**Success Criteria**:
  1. `python main.py` against all 63 portal configs completes and populates listings
  2. Extracted listings contain all required fields with validation
  3. scrape_runs table shows per-portal audit data
  4. Re-running upserts rather than duplicates
  5. Every listing has a populated embedding vector
**Plans**:
- 2-01: Foundation — Pydantic models, config, DB helpers (upsert, audit), test infrastructure
- 2-02: Validation, CanadaBuys CSV ingestion, embedding generation
- 2-03: LLM extraction (instructor + GPT-4o-mini), BidsAndTenders and generic browser scrapers
- 2-04: Orchestrator, CLI entrypoint, 5-portal live benchmark

### Phase 3: Search Layer (4 plans, complete 2026-02-24)
**Goal**: A validated search API supports hybrid keyword + semantic queries with the full filter suite, returning correctly ranked results from real listing data.
**Requirements**: SRCH-01 through SRCH-10
**Success Criteria**:
  1. Keyword query returns relevant results ordered by relevance
  2. Natural language query returns semantically relevant listings via pgvector
  3. Hybrid RRF search satisfies 20 real procurement queries
  4. All six filter dimensions work in combination
  5. Results sortable by 4 dimensions; default shows open/future only
**Plans**:
- 3-01: API foundation — FastAPI scaffold, DB connection, Pydantic models, Docker/nginx integration
- 3-02: Core search engine — hybrid search (keyword + semantic + RRF), filters, sort
- 3-03: Search UX — facet counts, keyword highlights with XSS sanitization, exact match, pagination
- 3-04: Integration validation — 20-query benchmark against real data

### Phase 4: Web Application (4 plans, complete 2026-02-24)
**Goal**: The BD team can log in, search all 63 portals from one dashboard, view listing details, and monitor scraper health — the platform is usable for daily work.
**Requirements**: DASH-01 through DASH-09
**Success Criteria**:
  1. Login, browse, filter, stay authenticated across sessions
  2. Listing detail with all fields, documents, contacts, source link
  3. "New" badge for unseen listings
  4. URL-encoded filter state for shareable searches
  5. Scraper health page with per-portal status and freshness indicator
**Plans**:
- 4-01: API extensions + Next.js scaffold with Auth.js, login, dashboard shell
- 4-02: Search page with nuqs URL state, filters, result cards, pagination, sort
- 4-03: Listing detail Sheet slide-out, "New" badges, data freshness indicator
- 4-04: Scraper health page with portal table, Docker Compose integration

### Phase 5: Scheduling and Hardening (2 plans, complete 2026-02-24)
**Goal**: The scraper runs automatically every night at 2 AM ET, Docker Compose is hardened for production, and old listings are cleaned up.
**Requirements**: INFR-05
**Success Criteria**:
  1. Scraper triggers at 2 AM ET nightly without manual intervention
  2. Docker Compose uses pinned digests, restart policies, log rotation
  3. Listings with closing_date > 1 year auto-deleted nightly
**Plans**:
- 5-01: Production Docker Compose overlay (restart: always, log rotation, digest pinning)
- 5-02: Nightly scrape script (flock, xvfb-run, retention cleanup), Docker prune, crontab installer
