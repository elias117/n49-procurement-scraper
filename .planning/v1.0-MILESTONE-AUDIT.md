## 4. Gaps

### Gap #1: reference_number Not Persisted (Non-blocking)

**Severity:** LOW — does not block any v1 requirement
**Details:** The scraper extracts `reference_number` from portals into `ProcurementListing.reference_number` and converts it to `ListingRecord.reference_number`, but:
- The database schema has no `reference_number` column
- `_listing_to_tuple()` in `scraper/db.py` does not include it
- The UPSERT_SQL does not write it

**Impact:** Reference numbers (e.g., CanadaBuys solicitation IDs) are silently discarded. Users cannot search by reference number. However, `source_listing_id` serves as the unique identifier for deduplication and is persisted correctly.

**Recommendation:** Add to v2 scope — create migration, update upsert, expose in search/detail.
